After a one-time setup of Google's Android Emulator, Kane CLI can run mobile tests on it locally. This guide is for **macOS on Apple Silicon (arm64)**, the only host that can run the emulator locally. For an overview of mobile testing, see [Mobile Testing](/docs/kane-cli-mobile/).

<Tip>
**Prefer not to set up a local device?** `kane-cli testrun run … --remote` runs the same mobile tests on a virtual device on a HyperExecute macOS host. It works from any machine and skips every step below. See [Remote Runs on the Cloud Grid](/docs/kane-cli-remote-execution/).
</Tip>

<Warning>
On Apple Silicon, always use an **`arm64-v8a`** system image. The x86 and x86_64 images do not run natively and are effectively unusable. This is the single most common setup mistake.
</Warning>

<Note>
The values on this page, API 35 and the Pixel device profile, are working examples, not the full list of supported Android API levels and device profiles. Confirm that a specific one is officially supported before you depend on it.
</Note>

## 1. Install Android Studio

Kane CLI does not ship an Android SDK, emulator, or system image. Install **Android Studio**, which bundles the Android SDK, the emulator, the system image manager, and the Device Manager. Download it from the Android developer site and run the first-launch setup wizard, which installs the SDK and `platform-tools`.

If you prefer a headless setup, install the command line SDK tools and use `sdkmanager` and `avdmanager` directly.

## 2. Install an arm64 System Image

Install a system image with the **`arm64-v8a`** ABI. In the Android Studio SDK Manager, tick an API level image whose ABI is `arm64-v8a`. From the command line:

```bash
sdkmanager "system-images;android-35;google_apis;arm64-v8a"
```

## 3. Create a Virtual Device

Kane CLI runs against an Android Virtual Device (AVD) that already exists. It does not create one for you, so create an AVD from the image you installed. In Android Studio, use **Device Manager → Create Device** and pick the arm64 image. From the command line:

```bash
avdmanager create avd -n kane_pixel \
  -k "system-images;android-35;google_apis;arm64-v8a" \
  -d pixel
```

## 4. Point Kane CLI at a Non-Default SDK Location

You need this step only if your SDK is not in the default location.

Kane CLI brings its own managed `adb`, so `platform-tools` and `adb` do not need to be on your `PATH`. Kane CLI only has to find the **emulator binary and your AVDs**. It looks for them in the default SDK location, `~/Library/Android/sdk`. If your SDK is somewhere else, point Kane CLI to it:

```bash
export ANDROID_HOME="/path/to/your/Android/sdk"   # only if not the default location
```

If your SDK is at the default path, skip this step.

## 5. Install the Kane CLI Test Tooling

Sign in and let Kane CLI install the tooling it manages for the emulator:

```bash
kane-cli login
kane-cli doctor --target emulator --install
```

You never boot the emulator or run `adb` yourself. Kane CLI finds the AVD, boots it, installs your app, and runs the test.

## Ready Check

Confirm Kane CLI sees a ready Android toolchain and, optionally, the AVDs on your machine:

```bash
kane-cli doctor --target emulator          # required checks, each with a fix if it fails
kane-cli devices list --target emulator    # the emulators Kane CLI can run against
```

When the Android checks pass and your AVD appears in the list, setup is complete. To use the AVD in a run, pass `--device-name "<name>" --os-version <v>` with the values exactly as the list prints them.

## Run a Test

```bash
kane-cli run "Add the first item to the cart" --target emulator --app ./builds/app-debug.apk
```

The emulator target accepts an `.apk` build or an uploaded app id, `APP` followed by six or more digits.

## Common Failures

| Symptom | Cause | Fix |
|---------|-------|-----|
| Emulator boots extremely slowly or hangs | An x86 or x86_64 image on Apple Silicon | Recreate the AVD from an `arm64-v8a` system image |
| `doctor` cannot find the emulator, or "No Android emulator found" when picking a device | SDK in a non-default location, or no AVD created yet | Set `ANDROID_HOME`, and create an AVD in **Android Studio → Device Manager** |
| Prompts to install Intel HAXM | Following an Intel Mac guide | Not needed on Apple Silicon. It uses the built-in Hypervisor.framework, so skip HAXM |
