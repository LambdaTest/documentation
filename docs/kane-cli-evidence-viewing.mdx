Sealed packs open in the hosted viewer. When you serve a pack with `kane-cli evidence serve`, the server runs only on your machine and nothing is uploaded: the viewer page reads the pack directly from your computer.

## After a run

When a run succeeds in an interactive terminal, Kane CLI asks whether to open the pack:

```text
View evidence in browser? (y/N)
```

Answer `y` to start a local server and open the hosted viewer on your pack.

Agent and non-interactive runs skip the prompt. Kane CLI prints this hint to stderr instead:

```text
evidence: view locally with `kane-cli evidence serve <path-to-pack>`
```

## `kane-cli evidence serve`

This command serves one or more sealed packs to the hosted viewer:

```bash
kane-cli evidence serve .testmuai/evidence/<execution_id>.evidence
```

```text
serving 1 pack on http://127.0.0.1:54321
<execution_id>.evidence
  pack    http://127.0.0.1:54321/<token>/<execution_id>.evidence
  viewer  https://evidence.lambdatest.com/?pack=http%3A%2F%2F127.0.0.1%3A54321%2F...
press Ctrl-C to stop
```

Open the `viewer` URL in your browser.

| Flag | Description | Default |
|---|---|---|
| `--port <n>` | Pin the local port | ephemeral |
| `--viewer-url <base>` | Override the hosted viewer base URL | environment's viewer |

`serve` accepts only sealed `.evidence` files. It rejects a pack directory that is still live and unsealed.

Exit codes: `0` when you stop the server cleanly with Ctrl-C, and `2` for any bad input or a port the server cannot bind.

<Note>
The server listens only on `127.0.0.1` and puts a random token, unique to each server instance, in the URL path. Nothing is uploaded anywhere.
</Note>

## The hosted viewer

The viewer at `https://evidence.lambdatest.com` is a static page. You can open a pack in three ways:

- a `?pack=<url>` query parameter, which is what `evidence serve` and the post-run offer construct for you,
- drag and drop of a `.evidence` file,
- a file picker.

The viewer remembers the packs you opened recently. It fetches only the parts of a pack it needs (using ranged requests), so even a very large pack opens after downloading a few kilobytes.
