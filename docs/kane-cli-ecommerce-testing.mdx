The costly bugs in a store rarely throw an error: a variant photo changes while the price stays old, a discount appears in the summary but the total does not drop, or a pickup slot is chosen and never reaches the order. These use cases check the parts of a store that have to agree with each other, across search, cart, checkout, orders, and the admin side.

Every use case below was recorded against a demo storefront and comes with the `_test.md` file that produced the run. Each step in the file is written in natural language and ends with a check, so Kane CLI fails the run when what the shopper sees stops matching what the store recorded.

## Run these recipes

Save any recipe below as a file ending in `_test.md`, change the `url` to your own store, and replace the product names and prices with values from your catalog. Then run it:

```bash
kane-cli testmd run tests/add-to-cart-with-variant_test.md --agent
```

The first run authors each step and records it. Later runs replay the recording without calling the model, so the same file works as a regression check in CI. To run every e-commerce recipe as one suite, tag the files and run `kane-cli testrun run --tags ecommerce --parallel 4 --headless`. See [Test.md](/docs/kane-cli-testmd/) and [Batch Runs](/docs/kane-cli-testrun/) for the full format and flags.

<Note>
The same files run against a native app on an Android emulator or an iOS simulator when you add `target` and `app` to the frontmatter. See [Mobile Testing](/docs/kane-cli-mobile/).
</Note>

## Search and product pages

Search and product pages decide whether a shopper reaches the right item at the right price. These recipes check that the result, the product page, and the selection controls all describe the same product.

### Search to product page

A search that opens the wrong product page still looks like a working search. This recipe searches the storefront, opens the result, and checks that the title, brand, price, and buy box on the product page match the item that was searched for.

```markdown search-to-product-page_test.md
---
mode: testing

max_steps: 40
tags: [ecommerce, search]
---

# Search to product page

## Search the storefront
Type "headset" into the "Search ShopKart" box and press Enter, then verify the results page shows "1 result for “headset”" and a result titled "Wireless Gaming Headset 7.1".

## Open the product
Click the result "Wireless Gaming Headset 7.1" and verify the product page shows the title "Wireless Gaming Headset 7.1", the brand "Aurex" and the price "$79.99".

## Confirm the buy box is usable
Verify the buy box shows "In Stock" and both an "Add to Cart" and a "Buy Now" button are present.
```

Kane CLI fails the run if the product page shows a different title or price from the search result, or if the buy box is missing its Add to Cart or Buy Now button.
